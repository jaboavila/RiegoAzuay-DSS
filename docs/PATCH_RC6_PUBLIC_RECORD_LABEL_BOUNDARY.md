# RC6 patch: public record-label confidentiality boundary

## Trigger

RC5 passed all 31 internal candidate checks. Independent inspection of the extracted public preview nevertheless found that shared test source still contained one exact duplicate irrigation-system name from the restricted selector and three nonessential restricted surrogate IDs. The detailed registry files and exact coordinate fingerprints were absent, but those literal record-level labels contradicted the stated public boundary of synthetic fixtures plus aggregate selector counts.

## Correction

- Search and duplicate-name tests now derive their restricted-mode targets dynamically or use synthetic fixtures.
- The public interface placeholder no longer displays a restricted application ID.
- The application uses the configured scientific demonstration ID rather than hard-coded comparisons.
- The final release gate scans the extracted public package against system names, organisation names, and surrogate IDs in the restricted selector.
- The previously published Santul demonstration record and aggregate range endpoints are explicitly allowlisted; all other exact record-level labels are prohibited from the public package.

## Boundary

This patch changes test/configuration plumbing and release privacy checks only. It does not modify the scientific engine, equations, crop or soil parameters, weather acquisition, turn-feasibility calculations, interface outputs, retrospective experiment, or reported results.
